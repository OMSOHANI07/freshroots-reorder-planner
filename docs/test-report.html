QA test report

Freshroots Reorder Planner

Functional, security, accessibility, concurrency and load testing of the planner, its API, the Neon database and the ERPNext integration.

Tested 26 Oct 2026Build 20f144fRule book 2.2 Live: freshroots-reorder-planner.vercel.appERP: freshroots.m.frappe.cloud

Verdict

The rules engine is solid; the workflow around it is not yet safe for live orders. Every reorder rule, validation check and output check held across 300 random datasets and catalogues up to 5,000 SKUs, and the live site served 650 requests under load with no errors. But 1 critical and 2 high issues mean a plan can be approved by anyone, or end up both rejected and approved, and ERPNext sync is now switched on, so those approvals create real purchase orders.

Findings

CriticalSEC-A

Anyone can act as Raghav and approve a plan

What
The sign-in is a role picker; the API trusts an X-Role header that any browser or script can set. With ERPNext sync on, an approval by anyone creates real Draft POs.
Evidence
AUTH-1/AUTH-2: a request with X-Role: raghav and no other credentials is accepted.
Fix
Real sign-in (e.g. Google or email link) with roles stored server-side; until then, keep the URL private or switch ERPNext sync off.
HighBUG-2

Approve and reject at the same moment both succeed

What
Two clicks (two tabs, or approve then reject quickly) both pass the "still a draft?" check. Both report success; the plan ends up approved with POs while carrying the reject note.
Evidence
RACE-2, plan #18 on the development database: audit log reads created → rejected → approved.
Fix
Lock the plan row while deciding (SELECT … FOR UPDATE) or update only WHERE status = 'draft' and check one row changed.
HighBUG-3

Approving two plans at once fails with a server error

What
PO numbers are counted, not reserved, so simultaneous approvals pick the same number and the database rejects the duplicate. The failed approval is rolled back cleanly and can be retried.
Evidence
RACE-3: 3 plans approved together → 1 succeeded, 2 returned 500; no partial data left behind.
Fix
Reserve the number inside the same lock as BUG-2, or retry on a duplicate-number error.
MediumBUG-1

Formula injection in Excel and CSV exports

What
A product or supplier name starting with = becomes a live formula (for example a hyperlink) when the export is opened in Excel. Affects the plan Excel, PO Excel, plan CSV and PO CSV.
Evidence
SEC-2 ×4, marked as expected failures in the test suite until fixed.
Fix
Prefix text that starts with = + - @ with an apostrophe and store Excel cells as text.
MediumPERF-1

The plan list slows down as plans accumulate

What
Each plan in the list triggers its own database queries, about 115 ms per plan from a laptop (36 plans took 4.2 s) and about 16 ms per plan on Vercel. Home and Plans both load the full list.
Fix
Load approvals and SKU counts for all plans in one query, and page the list (latest 50).
MediumLIMIT-1

Large SAP uploads exceed Vercel's 4.5 MB request limit

What
5,000 SKUs with 52 weeks of sales is a 5.4 MB upload. The planner handles it in 2–3 s locally, but Vercel refuses request bodies over 4.5 MB.
Fix
Keep uploads to 16 weeks (all the rules need), or upload files directly to storage and process them from there.
MediumSEC-B

No rate limiting on the API

What
The load test reached 130 requests per second with nothing throttling it; uploads and Gemini explanations are the expensive calls.
Fix
Add Vercel's firewall rate limits for /api/runs and /explain once real sign-in exists.
LowBUG-4

A repeated approval can return a server error instead of "already decided"

What
10 simultaneous approvals of one plan: data stayed correct (3 POs), 8 got a clear 409, 1 got a 500.
Fix
Resolved by the BUG-2 lock.
LowPERF-2

Cold starts of 6–7 seconds

What
When Vercel starts a fresh copy of the Python backend, the first request waits 6–7 s (p99 at 20 users). Warm requests take 160–400 ms.
Fix
Keep one instance warm, or load pandas only when a plan is run.
LowPERF-3

Submitting a PO to ERPNext takes about 7 seconds

What
Live check: create 2.1 s, update and submit 7.3 s. The button shows "Submitting…" throughout, so it's usable, but it feels slow.
Fix
Send rates and submission in one ERPNext call.
LowA11Y-1

Plans list isn't announced as a list to screen readers

What
List items are wrapped in an animation container instead of sitting directly in the list (axe: list, listitem).
Fix
Put the animation on the list item itself.
LowA11Y-2

"More options" text is slightly low-contrast

What
Blue on light grey measures 4.31:1 on New run; the minimum is 4.5:1.
Fix
Use the darker blue already used on the Guide labels.

Recommended order of fixes

  1. SEC-A real sign-in, or switch ERPNext sync off until it exists.
  2. BUG-2, BUG-3, BUG-4 lock the plan and reserve PO numbers in one transaction.
  3. BUG-1 neutralise formulas in all Excel and CSV exports.
  4. PERF-1, LIMIT-1 batch the plan-list queries; document the 16-week upload or move uploads to storage.
  5. A11Y-1, A11Y-2, PERF-2, PERF-3, SEC-B as polish.

Not covered

  • Safari and Firefox (all browser tests ran in Chromium, including phone sizes).
  • A real Gemini outage on the live site (failures were simulated; the fallback is tested).
  • Real SAP exports beyond the October fixture and synthetic data.
  • Penetration testing beyond the cases listed, and Neon or Vercel outages.
  • Submitting a real PO with real prices (the live check used a cancelled throwaway PO).
